# 产品功能总结（基于当前已实现能力）

## 产品定位

这是一个以地图为主入口的个人乐图编年史产品。
核心价值是把“音乐发现（推荐）”和“个人听过历史（沉淀）”放在同一张世界地图上，并结合时间维度进行回看。

一句话概括：

> 用地图与时间轴重构个人音乐记忆与发现体验。

## 一、用户侧核心功能

### 1. 地图优先首页
- 首页直接进入世界地图，无需先搜索。
- 按当前视野和缩放级别展示代表专辑点位。
- 支持地图拖拽、滚轮缩放、手动刷新随机专辑。

### 2. 发现与收听双轨并行
- 地图上可直接对发现专辑执行：
  - 标记听过（Mark Heard）
  - 收藏（Favorite）
- 标记听过支持撤销（再次点击取消）。
- 收藏支持取消收藏。

### 3. 图层开关
- 支持三层数据独立显示/隐藏：
  - 漫游发现层
  - 听过记录层
  - 收藏层
- 保证同一张地图内可对比“系统推荐”与“个人沉淀”。

### 4. 搜索与筛选
- 搜索支持艺人 + 专辑双字段。
- 搜索结果合并：
  - 本地发现池结果
  - 外部补充结果（按需触发）
  - 个人历史记录
- 搜索支持多维筛选：
  - 标签
  - 年代
  - 地区（国家/城市）
- 搜索体验优化：防抖、缓存、可中止请求。

### 5. 收藏与历史抽屉
- 提供 Library 抽屉展示：
  - 收藏列表
  - 听过历史
- 支持按标签和地区过滤。
- 每条记录支持“定位到地图”。

### 6. 时间轴联动
- 底部时间范围滑块支持年份区间筛选。
- 地图点位与记录统计联动刷新。
- 支持“按人生阶段”回看音乐偏好变化。

## 二、数据能力与推荐机制

### 1. 发现池优先策略
- 首页发现数据优先来自本地 SQLite 的 `discovery_pool`。
- 本地池为空或不足时自动回退内置目录数据。
- 保障系统在弱外部依赖条件下可持续可用。

### 2. 抽样与分布策略
- 支持地理分簇抽样与权重控制。
- 支持国家偏好增强（preferred countries）。
- 支持同艺人去重、已听去重、已藏去重。
- 支持 seed 控制，刷新时换批次同时保持稳定性。

### 3. 外部搜索增益
- 默认本地优先，外部搜索由用户主动触发。
- 外部（MusicBrainz）补充结果可回写本地发现池。
- 形成“使用越多，池子越丰富”的增长闭环。

## 三、个人数据沉淀能力

### 1. 用户记录持久化
- 听过记录持久化到 `user_records`。
- 收藏持久化到 `user_favorites`。
- 支持按用户隔离读取，支持跨重启保留。

### 2. 艺人地理缓存
- 艺人地理信息缓存到 `artist_geo_cache`。
- 优先读缓存，未命中才请求外部 API。
- 缓存写入为 best-effort，不阻塞主流程。

### 3. 历史兼容与迁移
- 已支持历史 localStorage 收藏导入到新后端。
- 系统整体已完成从 Supabase 向本地 SQLite 收敛。

## 四、账号与权限能力

### 1. 轻量账号体系
- 支持本地注册、登录、登出。
- 前端维持本地会话（LocalSession）并联动 API 鉴权。

### 2. 管理权限
- 发现池管理接口支持管理员邮箱白名单控制。
- 未配置管理员列表时，默认允许本地管理（便于部署与演示）。

## 五、运营后台能力（Geo Manage）

### 1. 发现池管理页面
- 提供 `/manage/discovery` 页面。
- 支持搜索、刷新、逐条编辑、删除。

### 2. 可编辑字段
- 国家/城市/区域信息
- 地理粒度（city / region / country）
- 聚类 key（geo_cluster_key）
- 权重（weight）
- 启用状态（enabled）

### 3. 自动校正规则
- 修改地理字段时可自动重算 cluster key。
- 支持人工覆盖 cluster key，便于运营精调。

## 六、导入与增长能力

### Last.fm 导入（已实现）
- 提供导入接口，支持最近轨迹同步。
- 支持增量导入（fromUnix / 自动读取上次导入时间）。
- 导入结果输出统计：fetched / imported / skipped / failed。
- 支持失败样本回传，便于排障与数据修复。

## 七、稳定性与体验保障

### 1. 外部 API 弹性
- MusicBrainz 调用具备：
  - 超时控制
  - 重试机制
  - 结果缓存
  - 限流冷却
- 限流或网络异常时尽量降级，不阻断主流程。

### 2. 地图渲染与交互优化
- 点位稳定抖动 + 全局碰撞解算，减少重叠遮挡。
- 拖拽/缩放采用节流与阈值策略，减少闪烁和频繁重取数。
- 点位尺寸随缩放和密度自适应。

### 3. 错误处理
- API 错误结构逐步统一（`error.code/message/details`），前端可读性较好。
- 请求失败时尽量保留当前可视数据，避免界面突变。

## 八、当前产品阶段判断

### 1. 阶段结论
当前已不是仅验证概念的 Demo，而是具备完整主链路的可用产品：
- 发现 -> 收藏/标记 -> 沉淀 -> 回看 已闭环。

### 2. 已具备的产品化特征
- 可持续数据资产（发现池 + 缓存）
- 运营可控能力（管理后台）
- 增长入口（Last.fm 导入、外部搜索补充）
- 可部署可迁移（本地 SQLite + Docker）

### 3. 下一阶段建议（产品视角）
- 更细粒度地理钻取（region/city 体验强化）
- 统计面板（流派、年度热度、区域偏好演化）
- 导入任务异步化与监控化（队列、重试、可观测）
